## How to read this file

Both a human and `tools\build\Invoke-ForgeBuild.ps1` read this file. Format is fixed:

```markdown
- [ ] **W0-XN** — one-line description
  - model: opus | sonnet | human
  - deps: W0-A1, W0-B2          (or: none)
  - wave: 0
  - reads: 02#3.1.1, 03#7.2     (document number # section)
  - touches: core/gateway/policy/**
  - done: `a command that must exit zero` and the specific thing it must prove.
```

- **The parser ignores fenced code blocks**, so the `W0-XN` template above is not a task. It would be skipped anyway: a real task id must match `^W\d+-[A-Z]+\d+$` and `XN` has no trailing digit.
- **Tick a box only when its `done:` criterion actually passed.** The lane ticks its own; a human ticks the `model: human` gates.
- **`model: human` tasks halt the lane** (exit code 11) and write `.forge-build\NEEDS-DECISION-<id>.md`. They are decision points, not failures.
- **Order matters.** The lane runs the first task whose deps are all done. Two sequencing choices are deliberate and must not be "optimised":
  1. **Track F (write safety) comes before track I (tool volume)** — Phase 1 §10.5 item 7.
  2. **The write-path portal family (J7–J9) comes before DataTable, the palette and every route** — Phase 3 §14 closing note. The least demo-able portal work is built first. This will feel wrong around week three. Leave it.
  3. **`W0-C2` carries the consumer and credential-ref audit columns before it is marked done** — Phase 5, 02 §11.3. A later migration puts a schema discontinuity in the audit hash chain, which on SQLite is the only integrity mechanism there is. Do not split this into a follow-up task.
- `reads:` uses shorthand: `01` = `01_GOALS_AND_ROADMAP.md`, `02` = `02_TECHNICAL_ARCHITECTURE.md`, `03` = `03_UX_DESIGN_SYSTEM.md`, `04` = `04_AUTONOMY_MODEL_ROUTING_AND_TASKS.md`, all in `docs\build-plan\`.
